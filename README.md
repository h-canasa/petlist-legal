# PetList — Marketing Site & Legal Documents

Hosts the public marketing/landing page for the PetList mobile app at
`mypetlist.app`, plus the Privacy Policy and Terms of Service at stable
public URLs for App Store Connect / Google Play Console submission fields.
 
This repo exists only because the main `petlist` app repository is
private, and GitHub Pages is not available on a private repo without a
paid GitHub plan. This repo holds no app source — only the rendered
marketing page and legal documents.

- **`index.html`** (repo root) — the marketing landing page (PET-205).
  Hand-authored, not generated by `build.js` — see that file's own comment
  on why it's deliberately excluded from the build step.
- **`privacy-policy/`, `terms-of-service/`** — generated by `build.js` from
  `source/*.md`, see below.
- **`pet-id/`** — the public Pet ID Finder View (PET-477), see below.
  Hand-authored, static, not touched by `build.js`.

## Pet ID Finder View (PET-477)

`pet-id/` is a static, client-side-only page served at `https://mypetlist.app/pet-id/` — the
destination every printed/shared Pet ID QR code and URL points to. Scanning a Pet ID opens this
page with the payload in the URL **fragment** (`#v1.<payload>`), which browsers never send to
any server, so the finder's device is the only place the pet owner's details are ever decoded.
There is no hosted Pet ID backend and no server-side persistence of any kind.

**Source of truth**: the `petlist` app repo (private) owns the v1 payload contract —
`src/utils/pet-id-payload.ts` and the validators it composes from `pet-id-config.ts`,
`home-base.ts` and `temperament.ts`. `pet-id/payload.js` here is a hand-ported, faithful mirror
of that contract (decode-only — this page never builds or encodes a payload). **There is no
shared build step between the two repos**: if the mobile contract changes (a new field, a
changed bound, a new temperament id), `pet-id/payload.js` and its tests under `test/` must be
updated here by hand, in a companion commit carrying the same PET ticket key.

- `pet-id/index.html` — page shell and font loading.
- `pet-id/pet-id.css` — Finder-specific styles, deliberately isolated from `css/styles.css`
  (the marketing/legal stylesheet) — this is a different product surface, not a themed variant
  of the marketing page.
- `pet-id/payload.js` — the v1 decoder and semantic validator (mirrors the app; see above).
- `pet-id/sentences.js` — pure text builders for the conversational hero and If Found line
  splitting; no DOM, so it's unit-testable without a browser.
- `pet-id/main.js` — DOM bootstrap: reads `location.hash`, decodes it, and renders the page.
  Never uses `innerHTML` on decoded content, never sends decoded fields anywhere.
- `test/` — Node's built-in test runner (`node --test`), no Jest/Vitest added solely for this
  page. Decode/validation vectors for valid payloads were captured from the mobile app's own
  encoder, not hand-invented, so the tests prove this page reads real printed tags.
- **`ios/`, `android/`** — stable public store redirect routes. The Android
  route points to the Google Play listing for `com.petlist.app`.

## Source of truth 

The actual document content is authored and audited in the main
`petlist` repo, at `docs/privacy-policy.md` and `docs/terms-of-service.md`
(see those files' own "How this draft was produced" / "re-verified"
sections for what was checked against the codebase). The `source/`
folder here is a **copy**, not synced automatically.

## Regenerating after a content change
 
1. Copy the updated file(s) from the main repo:
   ```
   cp <petlist-repo>/docs/privacy-policy.md source/privacy-policy.md
   cp <petlist-repo>/docs/terms-of-service.md source/terms-of-service.md
   ```
2. Run the build script (uses `npx marked` — no local install needed):
   ```
   node build.js
   ```
3. Commit and push. GitHub Pages redeploys automatically on push to the
   default branch.

## Marketing image assets

The landing page uses eight AVIF marketing screenshots in
`assets/marketing/store/`. Each has a 320px fallback and an `-800.avif`
high-density version at quality 75. `dash.avif` is the hero image; the other
seven are the feature gallery and load lazily. The current dashboard also has
a JPEG derivative for Open Graph previews. The site header and legal pages use
the transparent PetList wordmark from the app's image assets, on a white
rounded surface for contrast against the dark header.

The older JPG screenshot, preview, mascot, and banner assets in
`assets/marketing/` are no longer used in the visible pages. They are retained
for now rather than removed as part of this visual fix. `build.js` generates
the legal pages only; it does not process marketing images.
